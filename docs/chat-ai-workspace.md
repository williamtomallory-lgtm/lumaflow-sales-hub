# Chat-AI 合并界面

## 信息架构

侧栏只保留 **Chat-AI**，替代“智能搜索”和“销售助手”两个入口。默认页面即 Chat-AI。顶部 Chat / Work 切换发生在同一个组件中；模型目录、Size、推理档位、输入区、附件和回答共用，不复制第二套聊天实现。

- Chat：自由文字问题、产品与资料检索；使用产品销售顾问的服务器指令与受控工具。
- Work：输入框内嵌产品销售顾问、微信客服、销售复盘、朋友圈运营四个角色。
- 从客户档案点击“分析最新消息”，进入相同页面的 Work，并明确显示选择的客户。身份上下文不等同于自动读取聊天历史。

## 交互与真实通信

模型菜单采用紧凑浮层，条目同时显示系列、参数规模和实际连接状态。旁边推理菜单支持五档按钮和滑杆。Pro 选择可达的本机 14B；不可用时禁用，不自动购买 API 或下载权重。

用户点击发送后，`useChat` 请求 `POST /api/v1/assistant/chat`，每次传入当前的 `modelProfileId`、`mode`、`agentRoleId`、明确选择的知识文件 ID 和可选客户 ID。后端验证白名单、输入预算、文件访问与角色工具权限，再调用本机模型。浏览器不发送伪造的 assistant/tool 历史。

实际执行模型、思考开关与生成预算来自响应头，不由前端臆测。回答中的产品卡、库存记录和引用只来自本轮工具返回。文件正文节选的覆盖范围可展开查看。JSON 工具来源会明确标记“演示数据”，不能作为真实报价或库存依据。

## 简洁不等于隐藏边界

- 资料和客户选择收进输入框加号，默认不展开。
- 选择文件后，文件名一直显示在输入框中，可移除。最多五份可读文件。
- 微信导入入口只在微信客服角色中显示，使用原生对话框；只读取主动提供的导出内容，不假装登录个人微信。
- 发送 / 停止、失败重试和超预算提示保留。中文输入法确认和 Shift+Enter 不触发发送。
- 生成中锁定角色、模型与档位；切换后清除旧回答，避免把旧结果归给新模型。
- “新问题”清除本轮答案、输入、文件与客户选择，不删除知识库原件。
- 每次是独立提问，当前没有自动回放上一轮或长期聊天记忆。
- Size 是参数规模而不是回答长度。更大的模型、更多预算并不保证答案一定正确。

## 主要文件

- `src/components/agent-workspace.tsx`：统一 Chat / Work 交互和真实流式回答。
- `src/components/model-runtime-controls.tsx`：共用紧凑模型 / Size 菜单和推理菜单。
- `src/components/sales-hub.tsx`：侧栏与客户入口统一接线。
- `src/components/smart-search-view.tsx`：旧调用方的薄兼容入口，不再保留独立页面。
- `src/config/ui-static.ts`：导航与显示文案。
