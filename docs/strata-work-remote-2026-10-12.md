## 推理与压缩

- [Strata](https://github.com/Niko1221/Strata) 固定源版本 `7695859aa13afb248bdb4d36f9b2e95707db079d`，使用 0.1.43 CUDA 12 引擎以兼容现有驱动。
- 用户接受的 [Qwen3.8 Flash Next Coder 精简权重](https://huggingface.co/ISTA-DASLab/Qwen3.8-Flash-Next-GSQ-RCO-Coder-GGUF)，源版本 `5348543e0147355ac9cbcb031184a3546350988e`。两个 GGUF 分片共 58,408,584,928 字节，远程下载后的 SHA-256 与官方元数据一致。
- 8K 上下文、CPU/GPU 混合、磁盘分页、MTP 辅助解码、有限常驻专家缓存。不是把整个模型放进 12GB 显存。Windows 可提交内存限制使实际常驻专家缓存只有约 1–2GB，仍依赖文件缓存和磁盘读取。
- `prepare-strata-inplace.py` 让 Strata 直接读取原始 GGUF 专家，避免另存约 23GiB 的重复 `experts.bin`；这属于存储布局优化，不是量化或删参数。
- `strata_ternary_codec.py` 实现 Bonsai PTQ1_0 三值编码与 Strata Q2_0 的数值无损桥接。PTQ1_0 为 128 元素/28 字节，Strata Q2_0 为 64 元素/18 字节，因此桥接到当前引擎后是 2.25 bpw，不是 1.75 bpw。编码/解码已和 Prism 运行库对照。
- `strata_ternary_pack.py` 将第 23 层的 gate/up/down 专家做逐组最小二乘三值拟合，再写入当前引擎可读取的混合精度索引。三个张量的有效权重减少 150,732,800 字节（约 144MiB），对应权重相对 MSE 为 17.8%–18.7%。原版分片保留，因此磁盘实际增加约 354MB 实验文件，不能把有效权重减少量当作释放的磁盘容量。
- 修复了原生专家索引必须含 `(n_expert 256, ...)` 的兼容性要求。压缩包已在远程真正加载，并通过算术、Python 函数、中文说明和工具调用协议测试。短样本输出约 3.6–5.8 token/s；缓存状态不同，不能据此宣称压缩加速。

压缩实验位于 `.local-data/strata-data/packs/coder-ternary-l23`。本次选择该实验包进行 Work 验证，模型菜单明确标为“三值试验”。这不是 Bonsai 的训练流程复现；没有给 Qwen 添加不匹配的激活旋转，没有完成全层压缩、校准训练或通用质量基准。未达到“完整 Qwen 通用能力无损保留”的结论。

后续将候选扩大为第 11、23、35、47 层，共 12 个专家张量，目录 `.local-data/strata-data/packs/coder-ternary-l11-23-35-47`。构建耗时 619.76 秒，有效权重减少 **871,628,800 字节**，专家池从 25,146,163,200 减到 24,274,534,400 字节。原版与候选分别通过同一组 8 项算术、JSON 排序、缺失字段、文档指令隔离、Python 函数、金额统计、长上下文提取、工具协议测试。该轮总时间为原版 80.37 秒、候选 75.71 秒；只有一次对照且存在操作系统缓存差异，不作为稳定加速结论。通过后在远程加载四层候选，页面明确标为“四层三值试验”。

格式依据：[Prism Bonsai 模型格式](https://github.com/PrismML-Eng/Bonsai-demo/blob/main/MODEL-FORMATS.md)，Prism llama.cpp 版本 `e8fd209c975c80aa7fb36a8423571ff3b1b7e955`。原始 Strata 配置备份为 `.local-runtime/strata/strata-coder-original.json`；需要恢复时，在无请求运行的情况下恢复该配置并重新加载 Strata。Bonsai 本身的模型文件未修改。

## Work 行为

参考 [Octop](https://github.com/TencentCloud/Octop/blob/main/README_CN.md) 的任务执行与可追踪状态思路，在现有 Work/CowAgent 中实现：

- 默认绑定已启用的本地 Agent；部署新增 `lumaflow-work`，工作区 `D:\LumaFlow\workspaces\work`，拥有读取、创建、修改权限。删除与命令执行默认未启用；用户可在智能体设置管理权限。
- 服务端持久化任务计划与真实工具回执；工具派发前先记为待返回，返回后记录成功或失败。完成步骤必须引用本轮真实成功回执，失败命令和超时不能充当完成证据。
- 历史对话保留执行记录；同一对话续接会带入最近检查点。中断后必须先核对文件状态，不自动重放副作用。检查点按本地目录或云端用户、对话、Agent 和项目隔离。
- 独立验收保存原始目标、实际文件 SHA-256 和语义覆盖结果。代码先检查写入/读回哈希、命令退出码、未完成计划、目标文件与失败回执；成功搜索不能替代文件证据。本地模型只做固定选项的要求覆盖判断，其证据 ID 必须属于通过事实检查的回执。验收不通过时，权威状态为 `partial` 或 `needs-review`，答复和历史也保留未完成项。
- 用户说“继续”时保留原始目标、上一轮验收缺口与已有成果；已成功操作不重复执行，未知副作用先查实际状态。
- 通用 Work 只暴露所需文件、文档、分析、检索、记忆工具，保留销售任务的受控业务工具；连续三次完全相同的工具调用触发收尾。
- 销售路由依赖服务端声明的角色能力。无销售角色的本地 Agent 保留知识查询和权限允许的电脑/文档工具；“库存管理程序”等编程任务优先走通用域。
- Work 的整项执行允许 5 分钟，推理强度仍独立控制；避免 Light 的旧 120 秒时限截断多步骤任务的最后总结。计划模式仍不执行工具。
- 本地模型登记文件 `.local-data/local-models.json`；示例在 `config/local-models.example.json`。只接受本机回环接口，模型 ID 由服务端登记；网页请求不能注入模型 URL 或密钥。
- Bonsai 与 Strata 按需加载，运行中请求持有模型，其他请求不能中途切走。Windows 管理进程退出后立即收束输出管道，避免模型已就绪而请求仍等待子进程关闭。

模型选择入口位于 Chat/Work 输入框底部。当前已登记 Bonsai 2 27B 与 Strata Coder；其他模型只有实际安装并登记后才显示，不把尚未安装的模型标为可用。

## TypeSafe 技能应用

按照 [TypeSafe 的窄判断与代码组合方法](https://docs.typesafe.ai/concepts/how-to-build-with-system-one)，将语义路由和要求覆盖与执行事实分开。Work 验收默认调用当前所选的**本机模型**，不调用 Jev。可选 Jev 摘要路由实现已提供，需要同时显式设置 `TYPESAFE_WORK_ROUTING=true` 与服务端 `TYPESAFE_API_KEY`；多行正文、附件标记、路径、日志、回执等输入直接留在本地。摘要检测是保守规则，不能保证任意自由文本都不包含私人信息，因此默认关闭。远程没有配置 TypeSafe key，本次未声称 Jev 已连通。原有知识库分类的独立 TypeSafe 选项仍按原配置运行。

本机命令的工作目录也必须在 Agent 的工作区或明确允许的目录内。这是目录边界检查；完整命令权限本身不构成操作系统沙箱。部署的 Work Agent 默认不启用命令或删除权限。
