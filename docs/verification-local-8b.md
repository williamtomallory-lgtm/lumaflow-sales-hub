## 真实模型证据

精确 SKU：实际模型选择 `getProductDetails` 和 `checkInventory`，不是模拟器脚本。工具返回 `LT-ARC-T18-BK`、`ARC T18`、库存 `126`，最终文本与工具结果一致。增加输出格式处理前两次热启动分别约 3.8 秒和 4.1 秒；这不是每个问题的速度承诺。

最终带按行格式处理的版本再次验证通过：首段文字 7.12 秒，总计 7.13 秒。短单行答复会在完整一行生成后显示；较长回复按行陆续显示。

自然语言：“推荐一款18W黑色轨道灯，查询库存并提供参数表和场景图资料，回复要注明SKU。”最终版本通过实际调用：

`searchProducts → getProductDetails / checkInventory / getProductAssets → 文字草稿`

验证脚本记录首段文本 12.5 秒、总计 33.0 秒；同一模型实际返回 `LT-ARC-T18-BK`、库存 `126`，并列出真实目录中的参数表和场景图名称。输出受长度、电脑负载、温度及冷/热启动影响。首次模型加载日志记录 37.69 秒，另有首次 GPU 预热开销。

所有调用都到本机 Ollama，响应头 `X-Model-Id=lumaflow-qwen3-8b:latest`、`X-Model-Profile=local-qwen3-8b`；当前数据源仍为演示 JSON。

## 测试中发现和处理的问题

1. 初始验证把精确 SKU 查询也强制要求为 `searchProducts`，但真实模型合法调用了详情与库存工具。验证已改为接受详情或搜索，同时仍严格检查实际库存工具结果，另设自然语言选型场景强制验证搜索链路。
2. 自然语言颜色“黑色”与目录“曜石黑”在结构化过滤中不匹配。复现模型的实际搜索参数后修复通用颜色映射，补正反例回归测试；不放宽明确色号或其他筛选条件。
3. 小模型会生成 `#` 附件占位链接，单靠工具说明和提示词未消除。服务端增加按行文本格式处理，把单行 Markdown 链接改为名称，保留数值和工具结果，并测试逐字符切分；不将此误称为模型自身保证或完整事实校验。
