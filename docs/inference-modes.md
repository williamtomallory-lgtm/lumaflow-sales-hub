# 模型参数规模与本地推理档位

模型参数规模（8B / 14B）、是否思考、生成预算是三个不同维度。这里不是模仿任何商业平台的会员等级，也不以答案更长作为质量证明。所有档位均可在本地免费调用已安装的开放模型，硬件、运行时间和电力仍由使用者承担。

## 当前调度

| 页面档位 | 8K 上下文生成上限 | 32K 上下文生成上限 | 8K / 32K 输入预算 | 默认最长等待 |
| --- | --- | --- | --- | --- | --- |
| Light | 1,024 tokens | 2,048 tokens | 4,000 / 8,000 字符 | 120 秒 |
| Medium | 2,048 tokens | 4,096 tokens | 4,000 / 10,000 字符 | 180 秒 |
| Ultra | 3,072 tokens | 6,144 tokens | 4,000 / 12,000 字符 | 290 秒 |

32K 档位只对服务端明确登记且确实按至少 24K 上下文运行的模型开放；当前本机 Bonsai 以 32K 启动，`.env.local` 也登记为 32K。生成预算仍受服务端 `LLM_MAX_OUTPUT_TOKENS` 上限约束。`LLM_TIMEOUT_MS` 可缩短等待上限。预算提高只代表允许更长生成，不保证质量或速度；长文档原件仍完整保存在知识库。

Qwen3 的基础思考开关并不等同于五级原生强度。适配器向 Ollama 发送 `reasoning_effort`，本应用再施加不同生成上限；Ollama 官方接口列出了受支持的控制字段。[Ollama 思考控制](https://docs.ollama.com/capabilities/thinking)、[兼容接口字段](https://docs.ollama.com/api/openai-compatibility)。

## 操作

1. Chat-AI → Chat 或 Work → 点击输入框右下的模型名称选择已连接模型。
2. 打开旁边的推理菜单，选择 Light、Medium 或 Ultra。
3. 输入任务，用加号选择知识文件，发送。服务端在响应头保留实际预算供诊断；普通对话界面不再显示冗长的预算说明。
4. 若出现“预算已用尽”，结果可能不完整，应缩小问题或调整档位后重新运行；不会用预填文本掩盖失败。

其他模型需由管理员显式登记能力与预算，并单独验证。通用 OpenAI 兼容接口没有可验证的原生思考开关时，不宣称已经启用或关闭。

## 实现与验收

- `src/lib/ai/inference-policy.ts`：前后端共享输入预算，服务端解析档位与 Pro 路由。
- `src/lib/ai/model-options.ts`：序列化真实后端参数；旧 fast/normal/deep 保持兼容，知识自动分类仍走快速路径。
- `src/components/model-runtime-controls.tsx`：模型系列、Size 和档位设置，不向浏览器暴露地址或 Key。
- `/api/v1/assistant/chat`：校验模式、模型与文本预算；返回实际模型、思考开关、输出上限和输入限制。原始思考内容不发送到浏览器，只显示生成状态及最终答案。
- `node scripts/verify-inference-tiers.mjs`：串行调用五档真实本地模型，核验模型路由、预算递增、流式最终答案及无原始思考泄露。测试题是简单合成算术，不代表复杂销售问题的质量评测。

调用只接受服务器白名单 ID，Pro 不会将本地客户资料发送到自定义外部服务。模型依然只能使用角色授权的只读业务工具与未持久化报价草稿；调高档位不扩大权限。
