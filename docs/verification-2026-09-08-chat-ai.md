## 真实模型和浏览器

1. 主项目 3000：`verify:local` 实际调用 8B 的 `getProductDetails` 和 `checkInventory`，返回 SKU `LT-ARC-T18-BK`、库存 126，与 JSON 工具结果一致，约 8.8 秒。业务源明确是演示 JSON。
2. 独立部署 3010：相同真实检查通过；与 14B 测试同时排队时耗时约 90.8 秒，不作为单请求性能结论。
3. 浏览器 Work / 销售复盘 / 14B / Medium：合成记录“30 套黑色轨道灯、预算未确认、周三测量、未报价未成交”返回真实三条复盘。响应回执为 `qwen3:14b`、Medium、思考开启、1,536 tokens、2,000 字符输入预算。模型建议中把周三测量改为“周三前”，说明草稿仍需人工核对，不能当作已确认日程。
4. `verify-inference-tiers.mjs`：五档调度全部通过。17×23 测试中 Instant 回答 491（错误），其余四档回答 391；算术正确 4/5，Extra High 未严格遵循只输出数字。保留原始结果，不替换错误答案、不宣称五档质量全部通过。
5. 生产浏览器桌面与手机未记录到运行时页面错误。菜单可关闭、选择 Pro 后可见模型切到 14B，生成期间配置锁定。

## 独立部署与安全回归

独立目录未复制 node_modules、环境文件或模型权重。实际下载官方便携 Node 22.23.2 并通过 SHA-256，随后 npm ci 成功。Ollama 0.33.3 压缩包使用已有缓存，重新核验 SHA-256 后解压；推理复用本机已有服务和权重。

真实流程覆盖：首次生产构建 → 3010 健康检查 → 重复运行复用 → 修改源码后只停止自己的记录进程并重建。根目录 `Start-LumaFlow.cmd -NoBrowser` 从其他当前目录运行也能复用 3000。主项目尝试占用独立部署 3010 被拒绝，3000、3010 与 Ollama 11434 均仍监听。

验收中修复：npm 空行导致安装退出、便携 Node 未进入子进程 PATH、启动命令未切换工作目录、PowerShell 7 JSON 日期导致进程归属误判、生成文件导致重复构建、测试文件 HeadersInit 类型错误。

另修复了 Next 生产请求 URL 被规范化为 localhost 时，127.0.0.1 页面请求被误拒绝的问题。只接受相同端口的严格 loopback Host，不信任任意 DNS 或代理头。localhost:3000、127.0.0.1:3000、127.0.0.1:3010 的同源空请求均到达验证层（422），恶意 Origin 均拒绝（403）；真实 127.0.0.1 模型请求成功。

## 保留的边界

- 新电脑入口目前针对 Windows 10/11 x64；不是跨全部操作系统的安装包，首次需要网络及足够空间。便携隔离目录测试不是另一台物理电脑的驱动验收。
- 14B 在 8GB 显存下可能混合 CPU/GPU，明显慢于 8B；Size 或预算更大不保证答案正确。
- 未配置 PostgreSQL，当前业务库仍是 JSON 演示；上传知识文件另存本机，不上传 Git。
- 本次页面合并不实现个人微信实时聊天连接、自动发送、自动发朋友圈、长期对话记忆或完整 CRM 写入；这些应单独实施和验收。
