# Work 能力中心

Work 的“能力中心”是 LumaFlow 内访问本机 Octop 引擎的入口。它保留现有 Work、Chat、CowAgent 和 Knowledge 页面，在 Work 页面打开一个原生面板，通过本机引擎返回的 section 列表进入专家、团队、技能、知识和设备等功能。入口只接受 loopback 引擎地址；公共网站不会把访问者的浏览器指向访问者自己的 `127.0.0.1`。

能力中心通过以下边界工作：

- 页面先读取 `/api/v1/work-engine` 的真实连接状态和能力列表；未连接或未安装时只显示状态和重试入口。
- 用户可以在“你想做什么？”中请求功能入口建议。建议只产生一个可选的入口，不会自动执行任务、创建配置或授权第三方服务；无法达到可信置信度时回到左侧功能列表。
- 进入本机控制台前由本机 iframe 发出 ready 消息，服务端严格校验引擎 origin 和 iframe source 后签发短期会话凭据。凭据只交给本机控制台，不写入 Work 历史、浏览器持久存储或页面文字。
- 现有 LumaFlow Chat、Work 历史、CowAgent 名单、Knowledge 文件和产品数据保持原有存储与访问路径。Octop 的运行数据使用独立的 `.local-data/octop` 目录；接入入口不自动迁移、覆盖或删除旧数据。

## 18 项能力

服务端负责返回每一项的实际路径、可用性和说明。客户端使用服务端返回的路径，不根据名称自行拼接地址。下表是 Work 能力中心需要覆盖的功能范围；“可用”要以远程电脑当次状态为准。

| 能力 | 用途 | 可能需要的本机条件 |
| --- | --- | --- |
| 专家执行 | 让专家调用工具、技能和本地模型完成任务 | 本地模型和工具权限 |
| 专家库 | 创建、编辑和管理专家 | 专家工作区与模型配置 |
| 专家团队 | 主持人派工、成员执行和汇总 | 已创建的团队成员 |
| 长期记忆 | 查看、检索和维护专家工作区记忆 | 对应专家工作区 |
| 技能 | 管理技能包和子智能体资源 | 技能包文件与权限 |
| 插件 | 管理内置或第三方插件 | 插件安装和启用配置 |
| 定时任务 | 创建周期任务并查看运行结果 | 任务执行器和本地模型 |
| 连接器 | 管理文档、邮箱、Notion 和自定义 MCP 等连接 | 用户实际授权账号或 MCP 配置 |
| 知识库 | 导入、检索和共享私有资料 | 文件、解析器和存储空间 |
| 浏览器 | 使用本机 Chromium 浏览、截图和操作网页 | 已安装浏览器与持久会话 |
| 终端 | 交互式终端和 AI 辅助命令执行 | 终端权限与审批策略 |
| 桌面控制 | 查看或控制引擎所在电脑的桌面 | Windows 桌面会话和桌面权限 |
| 编程助手 ACP | 配置 Codex、Claude Code、OpenCode 等 Runner | 对应 Runner 已安装并登录 |
| 消息通道 | 管理微信、企业微信、飞书、钉钉、QQ 等通道 | 相应账号凭据和通道服务 |
| 模型 | 查看本地模型并切换模型配置 | 本地模型网关、显存和运行时 |
| 用户和权限 | 管理本机用户、角色和授权 | Octop 管理账号 |
| 设置 | 配置工具审批、运行限制、存储和服务器 | 管理权限 |
| 备份迁移 | 备份或迁移专家、记忆、技能、知识和定时任务 | 可写的备份位置；云存储需另行配置 |

## 配置边界

能力中心提供入口不会替用户完成外部服务登录。连接器、消息通道、浏览器持久会话和第三方插件都需要用户在远程电脑上实际授权。ACP 需要用户安装并登录对应 Runner；Docker 任务需要用户安装 Docker、授予权限并准备镜像或运行参数；云存储需要用户配置账号、桶或同步目标。没有这些条件时，页面应显示待配置或不可用状态，不应把入口显示成已经连通。

本地模型也按运行时状态处理。当前使用原有 Bonsai 2-27B；新增的 Qwen3.8 Flash Next Coder 已按用户要求撤下。其他本地模型只有在实际安装并登记后才进入可选列表，是否拥有足够显存和能完成实际推理，需要在目标远程电脑上逐项验证；代码中的模型名称或注册信息不等于推理已经成功。

## 远程验收状态

在远程电脑完成以下检查前，本项目不把 Octop 能力称为“已经部署完成”：

1. 启动独立 Octop 实例并确认只监听目标电脑的 loopback 地址。
2. 实测健康检查、引擎状态、模型列表和本机 Work gateway；确认返回的 section 路径与上游 dashboard 实际路由一致。
3. 在 Work 能力中心完成 iframe ready、短期会话握手、左侧导航切换和关闭/重试流程。
4. 对专家、团队、技能、知识、定时任务、浏览器、终端、桌面、ACP、连接器和备份分别做最小真实操作；需要账号、Runner、Docker 或云存储的项目在未配置前标记为待配置。
5. 用本地模型完成至少一条实际 Work 任务，并确认旧的 Chat、CowAgent、Knowledge 数据仍能读取、写入和恢复。

截至这份文档编写时，以上远程最终验收仍应按目标电脑的实际日志、页面和文件回读结果确认；文档中的能力清单描述接入范围，不代表每个第三方服务已经连接。
